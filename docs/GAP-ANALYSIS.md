# Анализ соответствия ТЗ v2.0

Дата: 2026-11-15  
Текущая версия проекта: 0.1.0  
Каноническое ТЗ: `docs/TZ.md`

## 1. Что уже реализовано

- Telegram-бот на aiogram 3, запуск через Docker Compose.
- PostgreSQL, Redis, S3-совместимое хранилище (RustFS), ClamAV.
- 4 системные категории: Холодка, 2й Этап, Клоузеры, Общее.
- 4 системные группы: GROUP_HOLODKA, GROUP_SECOND_STAGE, GROUP_CLOSERS, GROUP_GENERAL.
- Роли SUPERADMIN / BOSS / EMPLOYEE (enum в `users.role`).
- Авторизация по Telegram ID, блокировка пользователей.
- Базовый Permission Service: Default Deny, проверка группы для категории.
- Главное меню, категории, типы информации.
- Универсальные записи и динамические поля (фактически TEXT / PASSWORD).
- CREDENTIALS и SIP: базовые поля, AES-256-GCM для секретов.
- Карточка записи, показ секрета с аудитом.
- Поиск по названию/описанию/полям.
- Избранное.
- Архивирование и мягкое удаление.
- Загрузка/скачивание файлов через S3.
- Импорт/экспорт CSV (базовый).
- Управление пользователями: добавление, роли, блокировка, группы.
- Аудит (таблица `audit_logs`, часть действий).
- ARQ worker: бэкап CSV и очистка архива.
- Базовые тесты шифрования.
- Документация по деплою на Oracle Cloud.

## 2. Критические пробелы

### 2.1. Модель данных

Не хватает таблиц:

- roles, permissions, role_permissions, user_permissions, user_group_permissions
- category_permissions, category_group_permissions, category_user_permissions
- record_permissions, record_group_permissions, record_user_permissions
- tags, record_tags, record_versions
- files, file_versions, record_files, file_access_logs, file_scan_results
- recent_records, user_settings
- import_jobs, import_errors, export_jobs
- security_events, backups, system_settings, encryption_key_versions, background_jobs

Текущие модели не поддерживают:

- запись-уровневые права;
- теги;
- вложения и версии файлов;
- историю версий записей;
- подкатегории;
- пригласительные токены;
- статистику и уведомления.

### 2.2. Права доступа

- Нет Mixed Access на уровне записей.
- Нет AccessMode (ALL_EMPLOYEES / BOSSES_ONLY / GROUP / SELECTED_USERS / PRIVATE).
- Нет индивидуальных разрешений. `access_mode` в модели есть, но не используется.
- BOSS не видит все рабочие разделы автоматически (зависит от групп).
- Нет проверки прав на файлы.
- Нет инвалидации кеша разрешений.
- Нет проверки прав на каждый callback.

### 2.3. Интерфейс

- `/start` не даёт меню EMPLOYEE/BOSS — только SUPERADMIN.
- Главное меню не фильтрует категории по правам.
- Нет отдельных меню BOSS и SUPERADMIN по ТЗ.
- Нет пагинации, сортировки, фильтрации.
- Нет подтверждений опасных операций.
- Нет отмены FSM и тайм-аутов.
- Нет поиска внутри раздела.
- Нет управления категориями/подкатегориями.
- Нет архива как отдельного раздела.
- Нет статистики, истории изменений, полного аудита, бэкапов, состояния сервисов.
- Нет копирования логина/пароля отдельными кнопками.

### 2.4. Записи

- FSM добавления неполный: нет выбора подкатегории, тегов, видимости, групп, вложений, предпросмотра.
- Нет всех типов полей (LONG_TEXT, URL, EMAIL, PHONE, NUMBER, BOOLEAN, DATE, DATETIME, JSON, FILE_REFERENCE, MULTISELECT).
- Нет редактирования отдельных полей.
- Нет истории версий и optimistic locking (version увеличивается, но не проверяется).
- Нет перемещения записей.
- Нет восстановления из архива через UI.
- Нет окончательного удаления с подтверждением.

### 2.5. Файлы

- Нет таблицы `files` и метаданных.
- Нет SHA-256, MIME/magic bytes, проверки расширения.
- Нет карантина и `file_scan_results`.
- Нет версионирования и нескольких вложений.
- Нет file_access_logs.
- Нет проверки прав перед скачиванием.
- Нет ограничений размера, защиты от path traversal и ZIP bomb.
- ClamAV подключён опционально, но результат не сохраняется.

### 2.6. Поиск

- Нет фильтров по категориям/типам/датам.
- Нет поиска по тегам, файлам, SIP Username, URL, ID.
- Нет точного поиска и многословного поиска.
- Нет фильтрации результатов по правам пользователя.
- Секреты не индексируются (это правильно), но нет защиты от раскрытия названий закрытых записей.

### 2.7. Избранное и недавнее

- Избранное не проверяет актуальность доступа.
- Нет таблицы `recent_records` и истории просмотров.
- «Недавнее» показывает последние записи, а не историю пользователя.

### 2.8. Импорт и экспорт

- Импорт только CSV, без XLSX/XLS/TSV/JSON/JSONL/XML/TXT.
- Нет предпросмотра, сопоставления полей, проверки дубликатов и отчёта об ошибках.
- Нет фонового выполнения и прогресса.
- Экспорт только CSV, без XLSX/JSON/ZIP, выбора полей/категорий/вложений.
- Нет отдельного привилегированного экспорта секретов.
- Нет `import_jobs`, `export_jobs`.

### 2.9. Шифрование

- AES-256-GCM есть.
- Нет версионирования и ротации ключей (`encryption_key_versions`).
- Поле `encryption_key_version` не используется.
- Нет отдельного аудита копирования секретов.
- Секреты отправляются в чат обычным сообщением без минимального времени показа/очистки.

### 2.10. Аудит

- `audit_logs` есть, но логируется не всё.
- Нет `security_events`, correlation ID, IP/устройства.
- Нет истории версий записей.
- Боссы не имеют отдельного рабочего аудита.

### 2.11. Администрирование

- Нет пригласительных токенов.
- Нет удаления/отзыва пользователя.
- Нет редактирования профиля.
- Нет просмотра доступных пользователю разделов.
- Нет управления системными настройками.
- Нет статистики.

### 2.12. Инфраструктура

- Нет Alembic-миграций (используется `create_all`).
- Нет lock-файла зависимостей.
- Нет healthcheck у bot/worker.
- Нет ротации логов и мониторинга.
- Нет автоматического бэкапа PostgreSQL/MinIO и восстановления.
- Нет шифрования бэкапов и внешнего хранилища.
- Нет rate limiting / throttling.
- Нет bandit/pip-audit/dependency scanning.

### 2.13. Тесты

- Только unit-тест шифрования.
- Нет функциональных, интеграционных, security, load, recovery тестов.
- Нет тестов ролей и групп.
