# Техническое задание — OFFICE VAULT / MillionersBot

## 1. Назначение

Корпоративная система хранения информации и управления офисными данными через Telegram-бота. Интерфейс — исключительно Telegram. Платформа — Linux VPS + Docker Compose.

## 2. Роли и доступ

- **SUPERADMIN** — полный доступ, управление пользователями, ролями, группами и доступами.
- **BOSS** — создание, редактирование, архивирование и удаление записей.
- **EMPLOYEE** — просмотр доступных записей и поиск.

Принцип **Default Deny**: доступ к категории/записи есть только при явно выданном праве (роль, группа, персональный доступ). Неактивные пользователи блокируются.

## 3. Разделы (категории)

1. Холодка
2. 2й Этап
3. Клоузеры
4. Общее

Внутри каждой категории — типы информации:

- Логины и пароли (CREDENTIALS)
- SIP и телефония (SIP)
- Ссылки (LINKS)
- Настройки (SETTINGS)
- Инструкции (INSTRUCTIONS)
- Файлы и документы (FILES)
- Прочее (OTHER)

## 4. Функциональность

### 4.1 Записи

- Создание записи с динамическими полями (название, описание, произвольные поля).
- Просмотр карточки записи.
- Показ секретных полей по кнопке с записью в аудит.
- Редактирование названия/описания.
- Мягкое архивирование и удаление (статусы ACTIVE / ARCHIVED / DELETED).
- Восстановление из архива.

### 4.2 Поиск и навигация

- Полнотекстовый поиск по названию, описанию и текстовым полям.
- Избранное (персональные закладки).
- Недавние записи.
- Профиль пользователя (роль, статус, группы).

### 4.3 Файлы

- Загрузка файлов в S3-совместимое хранилище (MinIO / RustFS).
- Скачивание файлов из хранилища.
- Опциональная антивирусная проверка ClamAV.

### 4.4 Импорт/экспорт

- Экспорт записей в CSV.
- Импорт записей из CSV с указанием категории.

### 4.5 Администрирование

- Список пользователей.
- Создание пользователя по Telegram ID.
- Смена роли (EMPLOYEE / BOSS).
- Блокировка/разблокировка.
- Назначение групп.
- Просмотр групп и участников.

### 4.6 Аудит

Все значимые действия логируются: создание/изменение/удаление записей, показ секретов, действия администраторов.

## 5. Безопасность

- Секреты (пароли, SIP-пароли) хранятся только в зашифрованном виде.
- AES-256-GCM, мастер-ключ из `MASTER_ENCRYPTION_KEY`.
- Проверка прав на каждый запрос.
- Файлы хранятся в S3-совместимом хранилище, а не в Telegram.
- Аудит всех действий.
- Секреты не попадают в CSV-экспорт (маскируются `***`).

## 6. Архитектура

```
Telegram → aiogram 3 → handlers → services → PostgreSQL
                                     ↓
                              Redis (FSM)
                                     ↓
                              MinIO / RustFS (файлы)
                                     ↓
                              ARQ worker (бэкапы, очистка)
```

Компоненты Docker Compose:

- `bot` — Telegram-бот (aiogram 3).
- `worker` — фоновые задачи (ARQ).
- `postgres` — PostgreSQL 16.
- `redis` — Redis 7 (FSM-состояния).
- `minio` — S3-совместимое хранилище (RustFS).
- `clamav` — антивирус (опционально).

## 8. Переменные окружения

См. `.env.example`. Ключевые:

- `BOT_TOKEN` — токен Telegram-бота.
- `SUPERADMIN_TELEGRAM_ID` — Telegram ID суперадмина.
- `DATABASE_URL` — PostgreSQL DSN.
- `REDIS_URL` — Redis DSN.
- `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`.
- `MASTER_ENCRYPTION_KEY` — 64 hex-символа (32 байта).
- `CLAMAV_HOST`, `CLAMAV_PORT` — опционально.

## 9. Запуск

```bash
cp .env.example .env
# заполнить .env
docker compose up -d --build
docker compose logs -f bot
```

При первом запуске создаются таблицы, 4 категории, системные группы и SUPERADMIN.
